很多企業都有個資政策、資料清冊、委外合約、教育訓練紀錄，也能在稽核前整理出一整套資料。問題是，文件存在不代表控制有效。真正被問到時，企業常常回答不出三件事：這項控制措施到底要防止什麼風險？最近一次實際執行是什麼時候？執行結果有沒有造成任何決策或改善？

個資治理若只停在制度文件，最後很容易變成看起來合規。制度真正成熟的判斷標準，是企業能不能用一組可重複、可追蹤、可回讀的控制措施稽核，證明日常作業確實按照承諾運作。這篇文章談的不是把稽核做得更繁瑣，而是如何把抽象的個資原則轉成可以驗證的管理活動。

## 一、為什麼個資治理需要控制措施稽核

個資風險通常不是因為企業完全沒有規則，而是規則和實際作業之間有落差。例如，政策寫著「僅於必要範圍內蒐集」，但表單仍要求填寫與服務無關的資料。委外合約寫著「服務終止後應刪除資料」，但沒有人確認雲端備份、測試環境或客服匯出檔是否真的清除。資料清冊列出一套系統，實際上部門已經用另一套試算表處理相同資料。

這些問題不能靠重新閱讀政策發現。政策是設計意圖，控制措施稽核則要檢查設計是否落地、執行是否持續，以及結果是否足以降低風險。稽核不是單純找錯，而是把治理活動拆成可驗證的問題。

一項成熟的稽核，至少要回答以下問題：

- 控制措施目標是什麼？
- 風險事件發生時，這項措施能阻止、偵測或降低什麼後果？
- 控制由誰執行，多久執行一次？
- 什麼資料可以證明控制措施真的執行過？
- 稽核人員如何判定通過、部分通過或不通過？
- 發現缺失後，誰負責改善，何時回測？

如果只能回答「我們有規定」，卻無法指出實際證據，這項制度大多仍停留在文件層次。

## 二、控制措施目標、控制措施活動與稽核程序

實務上最常見的錯誤，是把目標、活動和稽核程序寫成同一句話。三者的功能不同，混在一起就很難判斷稽核到底要查什麼。

| 層次 | 要回答的問題 | 例子 |
| --- | --- | --- |
| 目標 | 希望降低哪一種風險 | 未經授權的人員不應取得客戶個資 |
| 活動 | 平常實際做什麼 | 每月檢視高權限帳號與離職名單 |
| 稽核程序 | 如何驗證控制措施有效 | 抽查三個月份的權限報表，核對離職人員是否在期限內停權 |
| 稽核證據 | 用什麼材料支持結論 | 權限報表、工單、停權紀錄、主管覆核紀錄 |
| 改善行動 | 缺失如何修正 | 補強離職流程，設定人資通知與系統停權的服務水準 |

目標不應寫得太空泛。像是「確保個資安全」幾乎無法稽核，因為沒有明確的失敗條件。比較好的寫法，是描述資料、角色、時間和結果，例如「離職人員的系統存取權，應在收到離職通知後一個工作日內停用，並保留可回溯的處理紀錄」。這樣才有可能設計抽樣方法和判定標準。

控制措施活動也不宜只寫成「定期檢查」。定期是多久？誰檢查？檢查哪些欄位？發現例外怎麼處理？如果這些問題沒有答案，後續的稽核只能變成訪談，而不是有效性驗證。

## 三、從資料生命週期建立控制措施稽核查檢表

個資控制措施稽核可以依資料生命週期分層，避免注意力全部放在資訊安全權限，而忽略蒐集、利用、提供、保存和刪除等階段。

### 1. 蒐集階段

蒐集階段的稽核重點，不只是檢查表單上有沒有隱私告知，而是核對實際欄位、使用目的和服務流程是否一致。可以從三個角度抽查：

- 選取近期上線或改版的表單，核對欄位是否出現在資料清冊。
- 逐一確認每個欄位對應的業務目的，以及是否有不必要或重複欄位。
- 比較表單告知內容和後端實際使用方式，確認沒有出現告知範圍之外的新用途。

例如，客服表單原本只需要聯絡方式和問題描述，後來為了行銷分眾增加職業、年齡和消費偏好。這個變更不能只由行銷部門決定，還要回頭檢查蒐集目的、告知內容、保存期限、存取權限和後續提供對象。稽核若只看前台畫面，很可能看不到資料已經同步到另一個分析平台。

### 2. 利用階段

目的限制最難靠政策證明，因為問題常發生在資料已經進入系統之後。稽核可以選擇高風險資料集，追蹤它從來源系統到報表、行銷工具、客服工具和分析平台的流向。

優先選擇包含身分識別、財務、健康、精確位置或未成年人的資料，或選擇最近新增第三方服務的流程。抽查時要確認：

- 使用者角色是否與業務必要性相符。
- 匯出檔是否有明確用途、保存期限和刪除責任人。
- 測試資料是否使用真實個資，若使用，是否有去識別化或其他防護。
- 報表是否把不必要的欄位一起帶出。
- 新增用途是否觸發重新評估或更新告知。

### 3. 提供與委外階段

委外管理常見的錯覺，是把簽署合約當成控制措施完成。合約只能證明雙方曾經約定，不代表受託者真的按照約定處理。

稽核至少應把合約義務拆成可以驗證的項目：受託範圍、資料類型、分包商、存取權限、事件通報、協助當事人權利、保存期限、返還與刪除、稽核或查核權。對高風險受託者，還要抽查實際帳號、處理紀錄、刪除證明、弱點修補或事件演練結果。

如果受託者不願意提供完整內部資料，企業不能因此直接把控制措施結論寫成「符合」。可以改採獨立查核報告、認證範圍、控制措施聲明、抽樣訪談或服務管理紀錄，並記錄證據限制和殘餘風險。決策者要知道自己依據什麼資料接受風險，而不是把不完整資料包裝成完整合規。

### 4. 保存與刪除階段

保存期限控制措施最容易漏掉備份、資料湖、測試環境、郵件附件、個人電腦和供應商匯出檔。稽核時要先定義「刪除完成」的範圍。若企業允許備份依週期覆寫，就應說明備份中的資料不能被一般作業還原使用；若系統能立即刪除，則應保存刪除操作紀錄和失敗重試紀錄。

可以設計一個刪除案例，從已達保存期限的資料開始，確認：

1. 系統是否產生待刪除清單。
2. 業務單位是否檢查法律保留、爭議案件或稽核保存例外。
3. 刪除工作是否在預定時間完成。
4. 下游系統、匯出檔和測試環境是否同步處理。
5. 管理者是否能取得成功、失敗與例外紀錄。
6. 例外是否有期限，而不是永久保留。

刪除控制措施的成熟度，不在於每一筆資料都能瞬間消失，而在於企業知道哪些地方仍有資料、為何暫時不能刪、誰批准例外，以及何時重新檢查。

## 四、如何設計可重複的稽核程序

稽核不是一次性的專案。若每次都靠稽核人員臨場判斷，結果會因人而異，也難以比較不同期間的改善情形。建議每一項稽核程序至少包含以下欄位：

| 欄位 | 實務寫法 |
| --- | --- |
| 稽核目的 | 驗證離職帳號是否在規定期限內停權 |
| 稽核母體 | 本季所有離職人員及其系統帳號 |
| 抽樣方法 | 全數檢查高權限帳號；一般帳號採風險抽樣 |
| 稽核步驟 | 比對人資名單、服務台工單、身分驗證系統與應用程式紀錄 |
| 通過標準 | 停權時間符合期限，且保留完整處理證據 |
| 例外判定 | 逾期、無紀錄、帳號仍可使用或證據無法回讀 |
| 缺失分級 | 依資料敏感度、暴露時間、帳號權限和可被利用程度分級 |
| 回測要求 | 完成改善後，以新樣本或原失敗案例重新稽核 |

母體定義特別重要。抽樣三筆資料之前，必須先知道三筆是從哪個總體抽出來的。如果母體本身就不完整，抽樣結果沒有代表性。以權限檢查為例，不能只從資訊部門提供的已知帳號清單抽樣，還要考慮服務帳號、外包帳號、共用帳號、緊急帳號和應用程式內部角色。

抽樣不應只追求數量。高風險資料、高權限人員、近期變更、曾發生缺失的流程，都可以提高抽樣優先級。若某項控制措施在上一期失敗，下一期不應完全換一批樣本來證明平均表現變好，至少要追蹤原缺失是否真的關閉。

## 五、證據怎麼留，才不會變成另一堆文件

好的稽核證據有三個特徵：可以定位、可以回讀、可以連到決策。截圖不是不能用，但單張截圖常常缺少時間、範圍、操作者和系統來源，日後很難證明它代表什麼。

建議證據記錄至少保留以下資訊：

- 證據名稱與來源系統。
- 產生日期、資料涵蓋期間和時區。
- 產生人員與覆核人員。
- 稽核母體數量和抽樣邏輯。
- 證據是否經過篩選、遮罩或轉檔。
- 檔案雜湊或版本資訊，必要時保留原始匯出檔。
- 稽核人員的觀察、判斷和限制。
- 與缺失、風險接受或改善工單的關聯編號。

個資治理證據本身也可能含有個資。因此，證據庫不能被當成無限制的稽核資料夾。應依用途設定存取權限、保存期限、遮罩規則和刪除程序。尤其是權限報表、當事人請求紀錄、事件調查資料和員工資料，通常不適合讓所有稽核人員自由瀏覽。

## 六、缺失分級不能只看有沒有違規

稽核發現缺失後，最容易出現兩種極端：所有問題都列重大缺失，導致組織疲乏；或所有問題都列觀察事項，最後沒有人真正處理。分級應同時考慮資料敏感度、影響人數、暴露時間、可被利用性、控制措施可偵測性和是否為重複缺失。

| 判斷因素 | 問題例子 |
| --- | --- |
| 資料敏感度 | 是否涉及健康、金融、生物特徵或未成年人資料 |
| 影響規模 | 單一個案、單一部門，或全體客戶 |
| 暴露時間 | 幾分鐘、數日，或長期未被發現 |
| 權限範圍 | 一般查詢、批次匯出，或系統管理權限 |
| 控制措施可偵測性 | 是否有日誌、告警和覆核機制 |
| 重複性 | 是否為前期已發現但未有效改善的問題 |
| 外部義務 | 是否可能涉及通報、契約通知或當事人權利 |

缺失分級的目的，不是替問題貼標籤，而是協助分配處理速度和管理階層注意力。低敏感度資料的單次逾期，可能透過流程修正即可；但同一流程若連續三期逾期，就顯示控制措施設計或資源配置有系統性問題，不能只用個案補救結案。

## 七、稽核如何接到管理循環

稽核報告如果只放在稽核資料夾，價值很快就會消失。建議把結果接回治理會議和風險管理循環，至少追蹤四類指標：

- 控制措施覆蓋率：高風險處理活動中，有多少已建立並執行稽核。
- 控制措施有效率：稽核通過、部分通過與不通過的比例。
- 缺失逾期率：超過承諾期限仍未完成改善的案件比例。
- 重複缺失率：同一根因或同一控制措施在不同期間再次失敗的比例。

指標不能只看漂亮的通過率。若稽核範圍一直縮小，或稽核人員避開最難取得證據的系統，通過率升高不代表風險降低。管理階層應同時閱讀稽核覆蓋範圍、證據限制和未納入母體的項目。

比較有效的管理會議，不是逐項朗讀缺失，而是問三個問題：哪些失敗是個案，哪些反映制度性根因？哪些風險已被接受，誰接受、接受多久？下個期間要用什麼證據證明改善真的有效？

## 八、假設案例：從一張報表看出三個控制措施問題

以下是一個假設案例。某電商公司每月檢查會員資料匯出紀錄，報表顯示所有匯出都有主管核准，因此稽核人員初步判定控制措施通過。

進一步追查後發現，報表只涵蓋客服平台，不包含行銷自動化工具。主管核准欄位是事後補登，沒有原始申請時間。匯出的檔案會自動同步到分析平台，但刪除規則只設定在客服平台。這一個表面上的「有核准」，其實掩蓋三種不同風險：控制措施母體不完整、核准證據無法證明事前決策、下游保存與刪除未被納入。

若只用文件檢查，這個流程可能得到好看的結果。稽核人員會要求重新定義母體、追溯原始申請、抽查下游同步和刪除結果。最後的改善行動也不會只停在提醒主管確實核准，而會包含資料流盤點、權限整合、申請單欄位設計、下游保存規則和回測樣本。

這個案例提醒我們，稽核不只是確認某個欄位有沒有填，而是確認控制措施是否在正確的時間、對正確的範圍、產生足夠可靠的結果。

## 九、與 ISO 27701、GDPR 和台灣實務的連結

ISO/IEC 27701:2025 將隱私資訊管理系統定位為可建立、實施、維持和持續改善的管理系統，適用於個人可識別資訊控制措施者與處理者。這種管理系統思維，重點不只在於列出要求，也在於證明流程已經運作，並透過監測、內部稽核和改善維持有效性。

GDPR 的問責原則則直接要求控制措施者不只要遵守，也要能夠證明遵守。這也是為什麼處理活動紀錄、資料保護影響評估、處理者監督、權利請求程序和安全措施，都不能只留一份範本。企業需要保留足以說明當時怎麼判斷、採取什麼措施、如何確認有效的紀錄。

對台灣企業而言，個資法與相關法規要求應該轉換成自己的控制措施目標和作業證據。不能因為某個國際標準有條文，就直接把標準名稱當成合規結論；也不能因為沒有收到主管機關通知，就認定現行控制措施沒有問題。法規、契約、客戶要求和管理系統標準可以互相支援，但每一項要求都要回到實際資料流和責任分工。

## 能證明制度運作，才算治理

個資治理的成熟度，不是文件數量，也不是稽核前能不能快速整理出一個資料夾。成熟的治理制度，應該能讓企業在平常就知道資料去哪裡、誰能使用、什麼時候刪除、控制措施是否有效，以及缺失如何被修正。

稽核的價值，正在於把「我們有要求」變成「我們能拿出證據，說明要求如何被執行」。當稽核結果能夠回到流程設計、系統設定、供應商管理和管理階層決策，個資治理才不會只是合規文件，而會變成企業日常營運的一部分。
