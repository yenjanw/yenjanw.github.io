# 個資外洩後，企業最先要保住的不是聲譽，而是證據鏈

個資外洩事件發生時，企業通常先問三件事：要不要報警、要不要發新聞稿、要不要通知客戶。這些問題都重要，但如果一開始就急著對外說明，卻沒有先保住系統紀錄、確認資料範圍和建立決策時間線，後面的每一個判斷都可能失去依據。

我的實務判斷是：個資事故的第一階段，不是先證明公司沒有錯，而是先讓公司能夠說清楚發生了什麼、影響到誰、已經做了什麼，以及哪些事情仍然不知道。這四個問題，決定企業能不能控制損害，也決定日後面對主管機關、客戶、合作夥伴或訴訟時，是否有可信的紀錄。

這篇文章聚焦在企業的事件應變與證據管理，不把尚未生效的修法當成現行義務。現行《個人資料保護法》第 12 條已規定，公務機關或非公務機關知悉所保有的個人資料被竊取、竄改、毀損、滅失或洩漏時，應通知當事人；《個人資料保護法施行細則》第 22 條則說明通知方式與通知內容。2025 年 11 月 11 日公布的修正條文進一步增加通報、即時應變與紀錄保存要求，但官方法規資料仍標示施行日期未定，企業應把它當成制度設計的重要方向，而不是直接套用成今天的法定時限。

## 一、先把「發現事件」和「確認責任」分開

很多組織在事件初期會陷入一個錯誤順序：先等鑑識報告完成，再決定要不要通知當事人。問題是，鑑識往往需要時間，而資料外洩造成的風險不會等報告完成才開始。

現行個資法第 12 條使用的是「知悉」所保有的個人資料被竊取、竄改、毀損、滅失或洩漏，而不是等到公司已經完成全部責任歸屬後才處理。施行細則第 22 條也要求通知內容包括個人資料被侵害的事實及已採取的因應措施。這代表事件應變至少要同時跑兩條線：

- **事實確認線**：釐清哪一個系統、哪一段期間、哪些帳號或資料表受到影響。
- **權益保護線**：在合理掌握風險後，採取隔離、重設憑證、停止可疑連線、保護當事人的措施。

兩條線不必等到同一時間結束。企業可以在仍有不確定性的情況下，先明確說明已確認的事實、尚在調查的部分，以及已經採取的保護措施。反過來，如果把「還在調查」當成完全不行動的理由，反而可能讓損害擴大。

這裡要特別注意，通知當事人不是對外承認全部法律責任。通知的目的，是讓受影響的人知道事故，能夠評估自己的風險並採取必要防護。責任是否成立、是否違反安全維護義務，則是另一個需要依事實與法律分析的問題。

## 二、第一個小時要做的不是刪資料，而是保全資料

發現可疑外洩時，IT 人員很容易直接刪除惡意程式、清理帳號、重灌伺服器。這些處置可能有助於阻斷攻擊，但如果沒有先保存必要證據，就可能讓後續調查無法回答最基本的問題。

企業應在事件程序中預先寫清楚「先保全、再清除」的原則，至少包含下列資料：

| 證據類型 | 可能回答的問題 | 保存重點 |
| --- | --- | --- |
| 身分驗證紀錄 | 哪個帳號在何時登入 | 保留時區、來源位址、驗證結果 |
| 存取與查詢紀錄 | 讀取了哪些資料表或檔案 | 保留查詢時間、操作者與筆數 |
| 網路與防火牆紀錄 | 資料是否被送往外部 | 保留連線端點、傳輸量與封包摘要 |
| 應用程式紀錄 | 哪個功能觸發異常行為 | 保留請求識別碼與錯誤訊息 |
| 雲端服務紀錄 | 供應商端發生了什麼 | 取得原始匯出檔與服務商回覆 |
| 人員處置紀錄 | 公司何時採取了什麼措施 | 記錄決策者、時間與依據 |

證據保存不等於把所有資料無限期留下。企業仍要考量資料最小化、存取權限與保存目的。比較穩妥的作法，是由事件負責人建立一個受限制的案件資料夾，對每份檔案記錄取得時間、來源、檔案雜湊值或其他完整性資訊，並限制只有事件小組可以存取。

如果企業沒有成熟的鑑識工具，至少也要做到三件事：不要覆寫原始紀錄、不要讓多人直接修改同一份證據、不要只把截圖貼進聊天群組而沒有保存原始檔。截圖適合放在摘要裡，但不能取代原始紀錄。

## 三、事件時間線要記錄「不知道什麼」

事件報告常常只記錄已經發生的事情，例如凌晨 2 點發現異常、3 點停用帳號、6 點完成密碼重設。但主管機關或客戶真正會追問的，還包括公司在每個時間點知道多少、當時根據什麼做決定。

建議建立一份持續更新的事件時間線，欄位至少包括：

| 欄位 | 寫法示例 |
| --- | --- |
| 時間 | 2026-09-20 03:15，Asia/Taipei |
| 新增資訊 | 發現同一服務帳號從異常來源大量讀取會員資料 |
| 資訊來源 | 身分驗證平台原始紀錄，案件編號 SEC-2026-091 |
| 當時判斷 | 尚未確認是否有成功匯出，先封鎖來源並保留紀錄 |
| 採取措施 | 暫停服務帳號、通知值班主管、啟動鑑識 |
| 未知事項 | 受影響筆數、是否包含特種個人資料，待資料庫比對 |
| 下一步 | 由資料庫管理員在唯讀副本上進行範圍分析 |

「未知事項」很重要，因為它能防止團隊在壓力下把推測寫成事實。比如說，紀錄顯示有人查詢了一百萬筆資料，不代表一百萬筆都已經被下載；看到外部連線，也不代表資料一定已成功傳輸。報告應該區分已確認、合理推定與尚待查證三種狀態。

這種區分也能讓對外通知更準確。通知不必假裝企業已經知道所有細節，但不能把未確認的內容寫成肯定句。可以說「目前確認可能涉及姓名、電子郵件及配送地址，實際影響範圍仍在比對中」，而不要直接宣稱「所有客戶資料都已外洩」。

## 四、先判斷資料風險，再決定通知內容

資料筆數不是唯一判斷標準。一筆身分證號、醫療資料或金融資訊，可能比大量低敏感度資料更需要優先處理。企業應把資料類型、可識別程度、是否可被冒用、是否已有公開情形，以及攻擊者可能取得的工具一起納入評估。

可以用下列四個問題建立初步分級：

1. **資料是什麼？** 例如姓名、聯絡方式、帳務資料、身分識別資料或特種個人資料。
2. **資料是否能被直接使用？** 例如是否包含密碼、驗證碼、付款資訊或可重設帳號的資料。
3. **資料是否仍然有效？** 已過期或已撤銷的資料，風險可能不同，但不能因此直接視為沒有影響。
4. **當事人需要立刻做什麼？** 如果需要改密碼、留意詐騙、聯絡銀行或確認帳戶，就應在通知中清楚說明。

通知內容至少應讓當事人知道事故事實與企業已採取的因應措施。實務上，還應盡量交代可能涉及的資料類型、事件發現時間、目前風險、當事人可採取的行動，以及企業提供的聯絡管道。

通知不是行銷文案，也不是法律辯護書。避免使用「非常遺憾造成不便」這類沒有資訊量的開場，也不要在事實尚未確認時急著把責任推給外包商、駭客或個別員工。當事人需要的是能夠降低損害的資訊，而不是一段無法驗證的安撫文字。

## 五、供應商事件不會自動變成企業免責

現代企業的個資事故經常發生在委外服務、雲端平台、物流系統或客服工具。即使初步看起來是供應商的環境被入侵，資料控制與通知決策仍不能完全外包。

《個資法施行細則》第 7 條規定，受委託蒐集、處理或利用個人資料者，依委託機關應適用的規定為之；第 8 條要求委託機關對受託者適當監督，監督內容包括資料範圍、類別、特定目的、期間、複委託、事故通知與補救、終止後返還及刪除等事項，並應定期確認受託者執行狀況及保存確認紀錄。

因此，企業的事件應變計畫不能只寫「通知供應商」。至少要預先定義：

- 供應商發現事故後，應在什麼管道通知誰。
- 供應商應提供哪些初步資料，例如事件時間、受影響服務與資料類型。
- 誰負責統一對外通知，誰負責技術鑑識。
- 供應商能否保留紀錄、提供唯讀副本與配合訪談。
- 合約終止或服務切換時，如何確認資料與備份已處理。

如果合約只寫「供應商應遵守個資法」，卻沒有事件通知窗口、時限、證據提供方式和合作義務，事故發生時就只能重新談判。那通常是最不適合談判的時刻。

## 六、把修法方向轉成現在就能做的準備

2025 年 11 月 11 日公布的個資法修正條文，針對個資事故增加通報、即時有效應變與紀錄保存的規定，並授權主管機關訂定通知或通報的內容、方式、時限與範圍。由於官方資料目前仍標示相關修正條文施行日期未定，企業不應直接把未生效條文寫成現行法定期限；但可以先把修法方向轉成內部能力。

最值得先做的不是背新的時限，而是建立四個可被驗證的能力：

- **快速辨識**：知道哪些系統保存個人資料，以及誰能在夜間啟動事件程序。
- **範圍分析**：能從紀錄推估資料類型、期間、筆數與可能受影響的當事人。
- **即時控制**：能封鎖帳號、撤銷權限、隔離系統並避免證據被覆寫。
- **完整留痕**：能保存事件事實、影響評估、決策理由與已採取的措施。

這四項能力同時也是施行細則第 12 條所列安全維護方向的實務化版本。該條提到風險評估、事故預防通報與應變、內部管理程序、資料安全稽核、使用紀錄、軌跡資料與證據保存，以及持續改善。換句話說，個資事故不是只有危機公關部門的工作，而是平時資料治理是否真的能運作的壓力測試。

## 七、用一次桌上演練找出真正的斷點

企業不必等到真的外洩才測試程序。可以設計一個不含真實個資的桌上演練，例如：客服供應商通知某個 API 金鑰遭到濫用，初步確認有人查詢會員資料，但尚未知道資料是否被下載。

演練時，讓不同角色在固定時間內回答問題：

- 值班人員如何驗證這不是誤報？
- 誰有權停用服務帳號？
- 誰能取得雲端平台的原始紀錄？
- 法務何時加入，如何判斷通知必要性？
- 客服要如何回答尚未確認的影響範圍？
- 供應商不配合提供紀錄時，誰負責升級？
- 哪些主管機關或產業規範可能另有通報要求？

演練的成果不應只是「大家都有參加」。至少要留下觸發時間、完成時間、卡住的決策、缺少的權限、找不到的紀錄，以及需要修改的合約條款。下一次演練再檢查這些問題是否真的改善，才算把事故經驗變成治理能力。

## 結語：能說清楚，比說得漂亮更重要

個資外洩後，企業當然需要維持信任，但信任不是靠一篇修辭漂亮的聲明建立的。它來自企業能夠在混亂中保留證據、承認未知、及時控制風險，並把受影響的人需要知道的事情講清楚。

對管理階層來說，最該追問的不是「這次能不能不要通知」，而是「我們現在知道什麼、還不知道什麼、下一個小時要如何降低風險」。對資安、法務、個資與客服團隊來說，最有價值的準備也不是多寫一份厚重的政策，而是確保事件發生時，資料、權限、聯絡人和決策紀錄都找得到。

現行法律已要求事故發生後通知當事人，施行細則也要求通知內容與安全維護措施。修法後的通報與紀錄要求何時正式生效，仍要以行政院及主管機關公告為準。企業現在能做的，是先把證據鏈、事件時間線、通知模板和供應商合作機制準備好。真正的應變能力，不能在外洩發生後才開始建立。
