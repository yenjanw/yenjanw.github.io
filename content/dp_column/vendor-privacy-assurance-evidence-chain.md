# 委外個資監督不是填問卷：建立供應商隱私保證與證據鏈

企業把客服、行銷、雲端運算、薪資、人資、物流、支付、影像辨識或資料分析交給外部服務商之後，常見的第一個動作是寄出一份供應商問卷。問卷可能有幾十題，也可能有上百題，內容包括是否有資安政策、是否通過 ISO 27001、是否加密、是否有備份、是否發生過資安事件。

問卷收回來，採購就把結果放進供應商檔案；法務把一段「受託者應遵守個資法」放進契約；資訊部門收到一份 SOC 2 或 ISO 證書。流程看起來完整，真正需要回答的問題卻常常沒有被處理：這家供應商實際拿到哪些個人資料？它可以做什麼、不可以做什麼？發生事件時誰要在幾小時內通知誰？合約結束後，資料如何返還、刪除與驗證？如果供應商又交給下一家廠商，企業是否知道？

我的判斷是，委外個資監督的核心不是「供應商有沒有填完問卷」，而是企業能不能建立一條從資料流、風險判斷、契約要求、控制驗證到缺失改善的證據鏈。問卷只是蒐集資訊的工具，不是監督本身。

## 一、為什麼一次性問卷不夠

### 1. 問卷回答的是制度存在，不是控制真的運作

供應商回答「有資安政策」，只代表它有一份政策文件；回答「資料已加密」，仍然沒有說明是傳輸加密、儲存加密，還是只有部分欄位加密；回答「有事件通報流程」，也沒有說明流程是否在最近一年演練過、誰有權判斷事件嚴重性，以及通知是否能在契約要求的期限內完成。

如果企業只收集「有」或「無」，就很容易把文件存在誤認為控制有效。真正有用的問題應該再往下追：

- 控制的適用範圍是哪些系統、資料集與人員？
- 最近一次執行或測試的日期是什麼時候？
- 執行結果由誰覆核？
- 發現例外時，有沒有補救期限與負責人？
- 能不能提供不暴露機敏資訊的證據？

### 2. 供應商風險會隨服務變更

同一家雲端服務商，單純提供不含個資的郵件轉送，與處理完整客服對話、身分證字號、付款資訊的服務，風險完全不同。供應商原本只在台灣提供支援，後來為了降低成本，把客服轉到其他國家；原本只有主服務商，後來又增加分析、監控、備份與客服工單平台。若企業只在簽約前評估一次，後續的資料流變化就會被漏掉。

委外監督因此不能只是一個採購關卡，而要和產品變更、供應商續約、重大事件、資料用途改變與次處理者變更連動。只要資料類別、處理目的、處理地區、使用人員或下游服務發生重大變化，就應該重新評估。

### 3. 證書有範圍，不是整家公司都被證明

企業常把 ISO 27001、ISO/IEC 27701、SOC 2 報告當成供應商安全的快捷證明。但證書與報告都必須看範圍。它可能只涵蓋某個資料中心、某一套產品、某個法人或特定期間，未必涵蓋企業實際使用的模組、客服流程、備份環境與次處理者。

查看證書時，至少要確認適用法人、適用服務、地點、有效期間、控制範圍、例外事項及查核結論。若供應商只提供一張證書圖片，卻不願說明適用範圍，企業不能直接把它視為「已完成風險評估」。

## 二、先把供應商和資料處理活動連起來

供應商名單本身不能呈現個資風險。真正有用的盤點單位，是「某一項服務如何處理某一類個人資料」。同一個供應商可能同時提供低風險的電子簽核、高風險的人資背景查核與涉及敏感資訊的客服服務，不能用一個總分涵蓋全部情境。

建議企業建立一份委外個資處理登錄表，每一列至少包含下列欄位：

| 欄位 | 要回答的問題 | 常見遺漏 |
| --- | --- | --- |
| 業務流程 | 供應商支援哪一項作業？ | 只寫供應商名稱，不寫實際流程 |
| 資料類別 | 處理姓名、聯絡方式、帳務、健康或生物特徵資料嗎？ | 只寫「客戶資料」 |
| 處理目的 | 為什麼需要這些資料？ | 使用「提供服務」等空泛描述 |
| 供應商角色 | 是受託者、獨立使用者、共同決定者或其他角色？ | 把所有外部公司都叫做委外商 |
| 處理地區 | 資料儲存、備份、支援與遠端存取在哪裡？ | 只看主資料中心位置 |
| 次處理者 | 哪些下游服務商會接觸資料？ | 只看直接簽約對象 |
| 保存與刪除 | 服務結束後如何返還、刪除與驗證？ | 只寫「依合約辦理」 |
| 證據 | 企業要用什麼資料確認控制有效？ | 只有問卷，沒有測試或紀錄 |

台灣《個人資料保護法》第 8 條要求蒐集者告知個人資料利用的期間、地區、對象及方式。企業若無法掌握委外服務商如何處理資料，就很難把自己的告知內容、內部紀錄與實際作業對起來。[個人資料保護法全文](https://law.moj.gov.tw/LawClass/LawAll.aspx?PCode=I0050021)

這裡也要避免一個常見誤區：資料放在供應商的系統裡，不代表供應商就可以為了自己的目的自由使用。企業應把「為了履行企業指示而處理」與「供應商為自己的產品改善、分析、廣告或模型訓練而使用」拆開判斷。後者可能涉及不同的角色、法源、告知與契約安排，不能用一般受託條款一筆帶過。

## 三、建立風險分級，而不是要求所有供應商做同一套審查

如果每一個供應商都要求完整稽核、現場訪查、滲透測試報告與高階主管簽核，制度很快會因為成本過高而失去可信度。反過來，如果所有供應商只填一份簡短問卷，高風險服務又得不到足夠證據，同樣不合理。

比較實際的做法，是先用幾個可說明的因素分級。分級不是為了製造漂亮的分數，而是用來決定監督深度、證據種類、覆核頻率與例外升級方式。

| 風險因素 | 低風險情境 | 高風險情境 |
| --- | --- | --- |
| 資料敏感度 | 基本聯絡資料 | 健康、金融、身分識別或兒童資料 |
| 資料量與範圍 | 少量、單一流程 | 大量、跨多產品或全客戶資料 |
| 處理權限 | 僅能查詢、無法匯出 | 可大量匯出、刪除或修改 |
| 處理目的 | 嚴格依指示提供服務 | 供應商可自行分析或重複利用 |
| 營運依賴 | 可快速替代 | 中斷會影響核心業務或法定義務 |
| 下游鏈 | 沒有次處理者 | 多層次處理、地區分散 |
| 跨境因素 | 不涉及跨境存取 | 遠端支援、備份或客服跨境 |
| 事件影響 | 影響範圍有限 | 可能造成大量當事人權益受損 |

可以把結果分成三層：

1. **一般供應商**：使用標準問卷、基本契約條款與年度聲明，適合處理低敏感度且可替代的服務。
2. **重要供應商**：要求資料流、控制說明、事件紀錄、獨立查核報告或測試摘要，並由業務、資訊與個資窗口共同覆核。
3. **關鍵供應商**：除上述要求外，還要有明確的稽核權、重大變更通知、次處理者管理、事件演練、復原測試、刪除驗證與高階主管定期檢視。

分級結果要能被解釋。例如，不能只說「總分 82 分，所以是中風險」，而應該說明「因為供應商可存取完整客服紀錄、支援人員可遠端查詢、且服務中斷會影響當事人權利請求，因此列為重要供應商」。這樣下一次服務範圍變更時，才知道哪些因素需要重新判斷。

## 四、把契約寫成可以驗證的控制要求

契約條款的問題，通常不是沒有寫，而是寫得太抽象。像是「受託者應採取適當安全措施」「受託者應遵守相關法令」「受託者應於發生事件時儘速通知」都很常見，但發生爭議時，雙方會立刻回到三個問題：什麼叫適當？哪些法令？多久算儘速？

比較可執行的條款，應至少明確化以下內容：

### 1. 處理範圍與禁止事項

列出資料類別、當事人類別、處理目的、處理期間、處理地區、允許的操作，以及禁止的用途。若供應商需要使用去識別或彙總資料改善服務，也要說明資料是否仍可能回推個人、誰可以存取、保存多久，以及服務終止後如何處理。

### 2. 人員與權限

供應商應指定能接觸資料的人員類型、授權流程、離職撤權、特權帳號管理、遠端連線條件與查詢紀錄保存方式。不能只寫「僅限授權人員存取」，卻不要求供應商保存可供查核的紀錄。

### 3. 事件通知

事件條款要分清楚「發現可疑跡象」「確認個資事件」「服務中斷」「可能影響當事人權益」等不同時間點。企業要能取得事件時間軸、受影響資料範圍、控制措施、暫時性處置與後續改善，不要只收到一句「我們已經處理完畢」。

### 4. 次處理者與重大變更

供應商增加或替換次處理者時，應提前通知，並提供名稱、處理地區、服務內容與風險資訊。企業是否有反對、要求補充評估或終止特定服務的權利，也要寫清楚。GDPR 第 28 條把處理者的書面指示、次處理者授權、協助控制者履行義務、刪除或返還資料，以及提供稽核資訊列為契約的重要內容，可作為跨境服務合約設計時的參考。[GDPR 第 28 條](https://eur-lex.europa.eu/legal-content/EN/TXT/?uri=CELEX:32016R0679)

### 5. 稽核與證據提供

契約不一定要讓每個客戶隨時進場查核，但至少要規定供應商應提供哪些證據、多久更新一次、重大缺失如何通知，以及企業在合理原因下能否進行遠端或現場查核。證據包括獨立查核報告、控制測試摘要、改善計畫、事件演練結果、刪除證明與次處理者清單，不應只限於證書。

### 6. 終止服務與資料退出

終止條款要把主資料、備份、快取、測試資料、客服工單、監控紀錄、支援人員本機檔案與次處理者資料分開處理。供應商應說明返還格式、刪除期限、備份淘汰週期、刪除證明內容與抽查方式。如果企業無法把資料取回，或無法確認資料是否已刪除，就不能把服務終止視為風險已經結束。

## 五、證據鏈應該長什麼樣子

一套成熟的委外監督，不是把文件堆在共享資料夾，而是讓每一個重要判斷都能由前後連續的證據支持。以下是一條可供企業採用的鏈條：

1. **資料流證據**：資料從哪裡進來、經過哪些系統、由哪些人員或供應商存取、流向哪裡。
2. **風險判斷證據**：為何列為一般、重要或關鍵供應商，哪些因素造成高風險。
3. **契約證據**：資料範圍、用途限制、事件通知、次處理者、稽核與終止服務條款。
4. **控制設計證據**：權限模型、加密方式、保存設定、備份政策、事件流程與人員訓練。
5. **控制運作證據**：存取紀錄、權限定期覆核、刪除紀錄、事件演練、弱點修補與異常處理。
6. **獨立驗證證據**：外部查核報告、滲透測試摘要、內部稽核結果或第三方評估。
7. **改善閉環證據**：缺失責任人、完成期限、複測結果、逾期升級與接受風險的核准。

這條鏈的價值，在於把「我們相信供應商有做好」改成「我們能指出依據，說明目前知道什麼、不知道什麼，以及對未知風險採取了什麼處置」。

ISO/IEC 27701:2025 將隱私資訊管理系統定位為協助組織建立、實施、維持與持續改善隱私管理的架構，並同時面向個資控制者與處理者。它不能替企業決定特定法域的法律義務，但可以協助企業把角色、資料處理、責任、控制與持續改善串起來。[ISO/IEC 27701:2025](https://www.iso.org/standard/27701.html)

## 六、監督頻率應由事件觸發，不只看年度週期

年度問卷有用，但只靠年度週期容易錯過真正重要的變更。企業應建立觸發條件，出現下列情況時重新評估：

- 供應商新增高敏感度資料或擴大處理量。
- 供應商變更資料中心、客服地區或遠端支援模式。
- 新增或替換次處理者。
- 發生個資事件、重大服務中斷或高風險漏洞。
- 稽核報告出現重大缺失或重複缺失。
- 供應商要求把資料拿去做產品分析、模型訓練或行銷用途。
- 合約續約但服務內容已經與原始評估不同。
- 當事人權利請求、刪除要求或主管機關調查顯示流程可能失效。

監督頻率也不必一律相同。一般供應商可以每年更新聲明；重要供應商可按半年檢視關鍵指標；關鍵供應商則應在重大變更時立即重評，並定期檢查事件通報、權限覆核、備份復原、刪除與次處理者狀態。

## 七、常見失敗案例與修正方式

### 案例一：供應商有 ISO 27001，所以不再追問

問題不在於 ISO 27001 沒有價值，而在於企業沒有確認證書範圍是否涵蓋實際使用的服務，也沒有檢查隱私義務，例如目的限制、當事人權利協助、保存與刪除、次處理者通知。修正方式是把證書當成一項外部保證證據，再補上與企業資料流程直接相關的控制證據。

### 案例二：契約寫了事件通知，但供應商只在確認後才通知

如果契約沒有明確要求「發現可疑事件」就先通知，供應商可能等到調查完成、影響範圍完全確認後才通報。這可能讓企業錯過內部應變、主管機關通報或對外說明的時間。修正方式是設計分階段通知，先提供已知事實，再依調查進度補充。

### 案例三：服務商說資料刪除了，但沒有刪除證明

「已刪除」可能只代表前台資料庫看不到，備份、報表、測試環境、客服工單與次處理者仍可能保留。修正方式是先定義刪除範圍與例外，再要求供應商提供刪除執行紀錄、備份淘汰規則與必要的抽查結果。若技術上無法立即從備份移除，也要確認備份不可被一般作業復原或重新使用。

### 案例四：問卷由採購單獨完成

採購最熟悉商務條件，卻不一定知道資料流、權限、刪除與事件處理；資訊部門知道技術控制，卻不一定能判斷告知、目的或當事人權利。修正方式是採購、業務、資訊、法務、個資窗口與必要時的稽核人員共同決定風險與證據要求，並讓最後的接受風險有明確核准人。

## 八、企業可以用九十天建立第一版制度

### 第 1 至 30 天：先找出關鍵委外

不要一開始追求完整。先從客服、人資、支付、雲端資料庫、行銷平台、身分驗證、醫療或高敏感度資料服務開始。確認每個服務的資料類別、目的、地區、存取權限與次處理者。若資料流不清楚，先列為未知風險，不要用「依供應商說明」結案。

### 第 31 至 60 天：完成分級與契約差距分析

為供應商分級，建立一般、重要、關鍵三層證據要求。把現有契約與標準條款逐項比對：是否有用途限制、事件通知、次處理者、稽核、刪除、返還與協助履行義務。對高風險缺口設定負責人與期限，必要時由管理階層決定是否暫時接受風險。

### 第 61 至 90 天：實際測一個高風險流程

選一個不能只靠文件判斷的服務，做一次小型驗證。例如要求供應商說明一筆測試資料從匯入、查詢、匯出、備份到刪除的完整路徑；或者演練一個客服平台疑似外洩事件，檢查通知、決策、證據保存與下游聯繫是否真的可行。測試後把發現的問題改成控制、契約或流程改善，不要只寫成稽核觀察事項。

可以用下列指標追蹤制度是否逐漸運作：

- 已完成資料流盤點的關鍵供應商比例。
- 已完成風險分級且有核准紀錄的供應商比例。
- 高風險供應商具備有效契約與證據的比例。
- 重大變更在規定期限內完成重評的比例。
- 逾期缺失數量與平均改善天數。
- 事件通知演練中，從發現到初步通知所需時間。
- 終止服務後可取得返還與刪除證明的比例。
- 未知次處理者或未盤點資料流的數量。

這些指標不應被當成單純的績效排名。若企業只追求「完成率」，供應商可能會快速補文件，卻沒有改善控制。管理階層真正需要看的，是高風險缺失是否下降、重複問題是否被消除、關鍵服務是否有可行的退出方案，以及企業能否在事件發生時快速說明資料去了哪裡。

## 九、最後的判斷：監督是持續的責任，不是簽約附件

委外之後，企業仍然要對自己的蒐集目的、利用方式、當事人權利與整體治理負責。供應商可以協助執行，也可以提供控制與證據，但不能因為資料放在外部平台，就把企業的判斷責任一併外包。

一份完整的委外個資監督制度，至少應該讓企業在五個問題上說得清楚：

1. 我們交出去的是哪些資料，為什麼需要交？
2. 供應商可以做哪些事，哪些事明確禁止？
3. 我們如何知道控制真的有運作，而不只是文件存在？
4. 服務或供應商改變時，誰會知道、誰會重新評估？
5. 出事、刪除、終止或被調查時，我們能不能快速拿出證據？

如果答案只能指向一份年度問卷，制度還停留在文件收集階段。真正可用的做法，是把問卷降回它應有的位置：作為初步資料蒐集工具；再用資料流、風險分級、契約、控制測試、獨立驗證與改善紀錄，建立一條能經得起查核與事件壓力的證據鏈。這樣企業才不是把責任交給供應商，而是知道自己如何監督、何時介入，以及在資訊不足時如何做出有紀錄的風險決策。
